# ACT-1-Pick · 把零食袋放进零食盒

第 12–15 课那个任务的工装。任务句与约定表在课程正文里，⛔ 这里不复制一份，免得两处对不上。

## offline_eval.py · 碰真机之前先离线验一遍

训练跑完、摆 20 次真机测试**之前**先跑它。它只读数据集，不连机械臂，用**训练时留出的回合**回答：

| 它算什么 | 判什么 |
|---|---|
| **开环**：模型看一眼交出的 100 步，和示教里真实发生的差多少；并按「第几步」分别统计 | 学没学到示教。逐关节列出来，能看出是哪个关节不行 |
| **半闭环**：把模型自己的输出当关节目标反馈回去，画面仍来自数据集 | 误差会不会越滚越大 |
| **越界**：预测有没有跑到关节行程外；比示教见过的范围外推了多远 | 输出合不合法 |

```bash
.venv/bin/python ACT-1-Pick/offline_eval.py \
    --policy-path outputs/train/act_snack_in_box/checkpoints/last/pretrained_model \
    --dataset-repo-id "$HF_USER/so101_snack_in_box_v1" \
    --dataset-root datasets/so101_snack_in_box_v1 \
    --episodes 45 46 47 48 49 \
    --action-units degrees --model-dir models/so101
```

`--policy-path` 可以一次给多个，用来**挑检查点**——⛔ 别默认 `last` 最好，小数据集上它常已过拟合。

### ⛔ 三条必须知道的边界

1. **它证明不了任务会成功。** 没有 SO-101 的仿真环境，成功率只有真机能测。它挡的是另一类事故：
   训练跑偏、检查点选错、动作发散或越界——这些不该等到人站在机械臂前面才发现。
2. **`--episodes` 必须是训练时真的留出、没喂给模型的回合**，否则这个数只是背书成绩。
3. **单位不猜，必须显式给。** LeRobot 0.6.1 的 `so101_follower` 默认 `use_degrees=True`
   ⇒ 五个本体关节是**度**；而夹爪永远是 `RANGE_0_100` 的**百分比**
   （`so_follower.py` 里写死，不随 `use_degrees` 变）。早期版本默认 `RANGE_M100_100`
   ⇒ 六个都是百分比，官方的 `lerobot/svla_so101_pickplace` 就属于那一代。
   ⛔ 拿百分比的数字当度数报，整篇结论都是错的。

### 开发记录

2026-09-29 建。管线用官方 `lerobot/svla_so101_pickplace`（与本任务同构：双路 480×640、6 维、
pick-place）加一个只训了约 119 步的检查点验过跑得通：2 个回合 543 帧，CPU 上 18 秒。
⚠️ 那次的 horizon 曲线不单调（h=0 的 26.3 → h=50 的 15.7 → h=99 的 37.1），
因为欠训练的模型基本在输出平均轨迹——**那个形状是伪迹，不能拿去讲课**，
「分块越往后越难」要等真训练出来的模型再看。
